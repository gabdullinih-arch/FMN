# Качество и нефункциональные требования

Значения ниже разделяют подтверждённые ограничения и цели, для которых проекту ещё требуется измеримый критерий. Непроверенные цели не следует трактовать как гарантии.

| ID | Атрибут | Требование/ограничение | Проверка или статус |
|---|---|---|---|
| QA-PLAT-01 | Переносимость | Целевая и проверенная платформа проекта — Windows x64; другие ОС не заявляются поддержанными. | Ручная проверка сборки/запуска на Windows; версия окружения описана в `README.md`. |
| QA-OFF-01 | Автономность | Основные сценарии планирования и локальное хранение не требуют сетевого сервиса. | Архитектурная проверка; в продукте нет сервиса синхронизации. |
| QA-DATA-01 | Целостность | Пакетное backend-применение шаблонов и повторов должно быть атомарным. | `src-tauri/tests/bulk_operations.rs`. |
| QA-DATA-02 | Сохранность при запуске | Ошибка открытия БД/миграции должна быть явной; нельзя молча подменять пользовательскую БД пустой. | Проверить код запуска и негативные тесты инициализации; отдельный автоматизированный сценарий может отсутствовать. |
| QA-DATA-03 | Валидация | Интервалы имеют пятиминутную гранулярность; конец позже начала. | `tests-frontend/intervals.test.mjs`, `src-tauri/tests/storage_semantics.rs`, SQL constraints. |
| QA-DATA-04 | Ограничение ресурсоёмкости | Генерация повторов ограничена максимумом в 520 недель. | `tests-frontend/recurring-scenarios.test.mjs` и backend bulk tests. |
| QA-ERR-01 | Обработка ошибок | Ошибка записи/импорта/применения должна быть видна пользователю; отмена не должна выглядеть как успех. | Сценарные UI-тесты и ручная проверка отказа Tauri-команд; см. [трассировку](./traceability.md). |
| QA-LOC-01 | Локализация | Поддерживаются русский и английский; русский язык используется по умолчанию. | `tests-frontend/i18n.test.mjs`; проверить форматирование динамических сообщений отдельно. |
| QA-UX-01 | Используемость | Интерфейс рассчитан на стандартные desktop-размеры; основные действия доступны с клавиатуры. | Есть горячие клавиши и палитра команд; целевые размеры окна/контрастность/полная проверка доступности не специфицированы. |
| QA-SEC-01 | Локальная безопасность | Сценарии PlanScript не должны исполнять произвольный JavaScript или получать прямой доступ к SQL. | Проверки parser/runtime и тесты PlanScript; спецификация может описывать функции шире текущей реализации. |
| QA-PERF-01 | Производительность | Целевые объёмы календаря и допустимое время ответа пока не заданы. | Требует продуктового решения и замеров на репрезентативных данных. |
| QA-REC-01 | Восстановление | Резервная копия должна отклоняться при некорректном формате, без частичной записи. | Проверить backend restore и отдельные тесты повреждённых/несовместимых payload. |

## Критерии, которые ещё следует определить

- Максимальный поддерживаемый объём интервалов и время открытия календаря/поиска.
- Целевые минимальный размер окна, DPI-масштабирование и критерии доступности.
- Политика совместимости/миграции формата JSON-backup между версиями.
- Требования по шифрованию данных и резервных копий (в настоящее время отдельные гарантии не заявлены).
- Методика измерения надёжности и целевой уровень покрытия негативных сценариев.
